## 第四轮：菜单面板自适应 + GitHub Pages 发布

### 菜单框太大 → 自适应

- 根因：开始菜单/侠陨/通关三块面板是 **DOM 覆盖层**，用的是写死像素，
  而游戏画布按 `s` 倍缩放（480×270 → 480s×270s）——面板不跟着缩：
  | 视口 | 原面板 | 占画布 |
  |---|---|---|
  | PC 1920×1080 | 454×260 | 24%×24% |
  | PC 1366×768 | 454×260 | 47%×48% |
  | 手机横屏 812×375 | 333×321 | 50%×86% |
  | 手机竖屏 375×812 | 188×381 | 50%×**181%（溢出画面）** |
- 解法：`index.html` 里面板改用 CSS 变量 `--pw`(宽) / `--pf`(字号)，
  内部全部用 `em` 表达（字号缩放时排版跟着缩，不用 transform 拉 → 文字不糊）。
  `game.js` 的 `fitPanels()` 按画布实际尺寸算：宽 = 画布宽 42%（夹 200~420px），
  字号 = 宽 × 13/340（夹 10~15px）；再实测面板高，超画布高则等比收（字号不破 10px）。
  `resize()` 和 `refreshInputUI()`（键鼠/触屏两套文案行数不同）都调它。
- 实测四种视口全部 `overflowsViewport=false`，面板占画布 42%~53% 宽。

### 踩坑：TDZ 崩溃

- `const PANEL_SEL` 原本声明在文件后部（第 3730 行），
  但 `refreshInputUI()` 在模块加载第 861 行就调用 `fitPanels()` → 读 const 触发 TDZ
  → **整个 game.js 抛错、游戏完全起不来**（表现：只有菜单外壳）。
  修法：`PANEL_SEL` 提到文件头部与 `viewScale` 一起声明。
  教训：模块顶层有「加载即执行」的调用时，它依赖的所有 const 必须在前面。

### 黑边根因与修复

旧 `resize()` 一律 `Math.floor(raw)`：

| 分辨率 | raw | 旧画布 | 旧黑边(左右/上下) | 旧占比 | 新占比 |
|---|---|---|---|---|---|
| 2560×1440 | 5.333 | 2400×1350 | 160/90 | 88% | **100%** |
| 1920×1080 | 4.000 | 1920×1080 | 0/0 | 100% | 100% |
| 1600×900 | 3.333 | 1440×810 | 160/90 | 81% | **100%** |
| 1366×768 | 2.844 | 960×540 | **406/228** | **49%** | **100%** |
| 1280×720 | 2.667 | 960×540 | 320/180 | 56% | **100%** |

新策略：`const fl=Math.floor(raw); const s = (fl>=1 && raw-fl<0.005) ? fl : raw;`
—— 几乎正好整数才取整（保完美像素），否则按实际比例铺满。
同时去掉触屏分支的 `Math.min(raw, 2.4)` 上限（大屏平板上等于自加黑边）。
画布尺寸 `Math.round(LW*s)` 取整到设备像素，避免浏览器再做一次小数缩放。

非整数缩放下 `image-rendering:pixelated` 是最近邻 → 像素锐利但列宽略不均（2/3px 交替），可接受。

### 高分渲染（"文字模糊 / 整体糊"的根因）

backing store 一直是 480×270，靠 CSS 拉到屏幕尺寸 → 1366 屏上是 2.844 倍非整数拉伸，
`image-rendering:pixelated` 只会把 8px 的字拉成马赛克块。

改法（`applyHiDPI(cw, ch)`，在 `resize()` 里调）：
```js
const dpr = Math.min(devicePixelRatio || 1, 2);
const bw = Math.round(cw * dpr), bh = Math.round(ch * dpr);
ov.width = bw; ov.height = bh;
octx.setTransform(bw / LW, 0, 0, bh / LH, 0, 0);   // 逻辑坐标仍是 480×270
renderer.setPixelRatio(dpr); renderer.setSize(cw, ch, false);
```
- 绘制代码一行没改，fillText 以真实 22~24px 字号光栅化 → 矢量边缘，不再糊。
- WebGL 纹理本来就是 NearestFilter，放大后是干净像素块。
- **坑**：改 `canvas.width` 会重置全部 2D 状态（transform / smoothing），每次都得重设。
- **坑**：`capture()` 里 `drawImage(ov,0,0)` 必须补目标尺寸 `(...,LW,LH)`，否则裁掉大半。

## 第七轮：武器技能 vs 职业系统（定案）+ 心法设计

**用户问**：「设计武器技能系统还是职业技能系统，哪种更适合像素风？武器偏 ACT 爽感技巧，职业偏 RPG 构筑。」

**结论：不做职业，做三层结构。**
- 成长层 = 兵器专精 0→10 级（0 美术成本）
- 构筑层 = 心法 一主二辅（0 美术成本，540 种组合）
- 动作层 = 八兵器 × 八技能（复用现有）

**决定性理由（两条，以后有人再问职业就答这两条）**：
1. 职业必然锁武器 → 掉落的八类兵器七成变废品 → 核心掉落循环断掉。
2. 八职业要八套待机/行走/受击/三段攻击动作，像素风下几百帧；八兵器共用身体只换武器精灵与挥砍曲线。

**纯武器系统的真问题**是趋同（都收敛到最强那把），用心法补，不用职业补。

已写进 `SKILLS-STORY-PLAN.md` 第三章（22 条心法 + 数据结构 + P5.5 施工单 + 平衡验收 P95/P50 ≤ 1.35）。

### 设计骨架（三条，改之前先想清楚）

1. **一主二辅互斥**：12 × C(10,2) = 540 种组合。允许叠两条主心法的话，玩家一定会去找
   "哪两条乘起来最爆"，最后收敛成一个答案，构筑就没了。
2. **每条主心法必须有代价**：没有代价的那条会变成所有人的默认答案。代价必须**写在卡面上**，
   不能藏在 tooltip 里 —— 玩家是看着代价做选择的。
3. **强化只放大好处，不放大代价**（`lvMul()` 只乘正项）：血河 -15% 气血如果跟着注解等级走，
   练到 3 级反而更脆，玩家会觉得越练越亏。

### 代码落点

- `mantraMod(loadout, owned)` → 15 个字段**全加法**累加，单一来源上限 40%
  （追命 / 藏锋都压到 40% 顶格），取整到 0.1，`seen` 去重防主辅同 id 重复计。
- `computeStats()` 里折进 `stats()`：`atkPct/hpPct` 走乘法区，
  其余 13 项加法；**`qiMaxPct` / `qiRegenPct` 放最后乘一次**，
  否则装备给的 +真气 会被算漏。
- 五个机制钩子全部折进**已有三条路径**，没有另起一套战斗逻辑：
  `hitEnemy`（伤害乘区 + 命中后）、`hurtPlayer`（受击）、`update`（时间累积）。
- 状态类复用已有状态机：焚心用 `e.burn`、寒潭用 `e.slowT`，不新增状态。
- 一次性增益（藏锋 `mCangBonus` / 疾风 `mJiFengT`）**无论装哪条主心法都要吃掉**，

### 踩的坑（10 条）

1. **`hitstop` 冻结整帧**：`if (hitstop > 0) { hitstop -= dt; tickSwing(dt); return; }`
   连 `atkCd` 都不扣 → "这一刀停多久"直接决定八秒里能挥几刀，**同一组组合能差 55%**。
   平衡循环里必须每帧 `g.hitstop = 0`。
2. **`atkBase` 被升级累积**：前面几节杀过怪，每升一级 +2，基线悄悄抬高七成。
   `clean()` 里显式钉死 `atkBase = 8 + (lv-1)*2`。
3. **野怪一直刷**：200 组 × 8 秒 = 26 分钟游戏时间，AOE 打死刷出来的怪 → 升级。
   `resetCombat()` 把 `spawnT` / `eliteT` 推到 9999。
4. **时辰漂移**：晨雾偷袭 ×1.5、夜行怪属性跟时辰走，前后样本不在同一个世界。
   `comboDps()` 里 `g.setClock(0.5, 1)` 钉在正午。
5. **焚心扣 2 真气等于没代价**：命中本身回 3 真气 → 净 +1，真气永远不会不够。
   `params.qi` 改 **5**（净 -2），断言改成"净耗 2"。
6. **无常把冷却清零 → 最强组合 DPS 冲到中位数 2.3 倍**：30 秒大招变成几秒一发，
   一条心法顶掉整个构筑的差异。改成**剩余冷却减半**，概率 25% → 20%。
7. **寒潭 15%/2 秒的概率代价不成立**：攻速够快时 2 秒窗口首尾相接，减速几乎常驻，
   等于一条常驻 +20%。改 10%/1.5 秒/+18%。
8. **树妖 / 洞主分支不记 `bossKills`**：`yaowang` / `treant` 走自己的 `else if`，
   进不了 `e.boss` 分支 → 「归元」「寒潭」永远学不到。**真 bug，不是测试问题**。
   `checkMantraUnlocks()` 要放在 `killEnemy` 最后，早一步查会读到旧值。
9. **`sanitize()` 顺序**：先按"已学"过滤再校验装配，顺序反了会把槽一起清掉。
10. **`equipFam()` 随机滚词条 → 绝对值不可比**：`makeGear(..., Math.random, ...)`，
    每次加载页面拿到的剑都不一样，整条基线能差四成（连跑四次 P50 = 2943 / 3856 /
    4208 / 3331）。**比值不受影响**（同一次运行内自己比自己），但"改完数值有没有用"
    只能看绝对值 —— 绝对值在飘的时候，任何一次调参都看不出效果。
    修法：平衡段把 `Math.random` 整个换成固定 LCG 序列，跑完再还回去。
    **凡是要跨次比较的测量，先把所有随机源钉死**。

### 发布时踩的坑：`github.com:443` 被干扰

P5.5 的 commit `8b7e576` 正常推上去了，十分钟后推第二个提交就失败：
`Failed to connect to github.com:443` / `Recv failure: Connection was reset`。

排查结论（下次直接照这个走，别再从头试）：

| 目标 | 结果 |
|---|---|
| `https://github.com` | **000 超时**（被干扰） |
| `https://api.github.com/rate_limit` | 200，正常 |
| `https://codeload.github.com` | 301，通 |
| `https://718997675.github.io/xiaoyaoxing/` | 200，通 |
| `ssh -p 443 git@ssh.github.com` | TCP 通，`Permission denied (publickey)`（没配公钥） |

- `~/.gitconfig` 里 `http.proxy` / `https.proxy` 是**空值**（显式置空，盖掉环境变量
  `https_proxy=http://127.0.0.1:53936`），所以 git 一直直连。环境变量救不了。
- 结论：**`git push` 走的是 github.com，而 api.github.com 是通的** → 走 Git Data API。

已经做成工具 `dawn-s1/tools/push-api.js`：

```bash
node dawn-s1/tools/push-api.js          # 推 HEAD，SHA 与本地逐字节一致
node dawn-s1/tools/push-api.js --dry    # 只看要传什么
```

blob → tree → commit → ref 四步。两个关键点：
1. **author / committer 要连时区一起还原**，且 API 只认 `+08:00`，`+0800` 直接 422。
2. **消息要原样带上尾部换行**。第一次手工推时 `%B` 被 `trim()` 掉了一个 `\n`，
   远端生成的提交 SHA 和本地差一个字节 → 内容一样但分叉，还得再 `reset` 一次。
   工具现在会把两个 SHA 打出来对比，一致才算成功。

**长期解法**：配一把 SSH key 走 `ssh.github.com:443`，比 API 稳。
