## 傍晚：路线可行性实测 —— 「能不能直接拿传奇素材做帧动画」

用户问：能否直接拿传奇素材做帧动画，或者仿照传奇自己做帧动画。
**两条路都实际跑了一遍**，不是纸上推演。

### 路线 A：直接拿传奇素材（已跑通，但素材不能直接用）
- 流程：黑键 GIF → 亮度键 + **flood fill 抠背景** → PNG 序列 → 预加载 Image → 逐帧 `drawImage`。
  接进样片页，8/10/16 帧全部加载并渲染成功。
- **三个硬伤（都是实测看出来的）**：
  ① 传奇 GIF 是「**角色 + 特效 + 背景**」合体录像 —— 抠出来带角色/召唤物/别的元素
     （绿法阵那帧抠出来是「金翅凤凰 + 远处一个小金阵」），要干净得逐帧人工修图；
  ② 素材是给 **800×600 俯视场景**画的，我们是 320×180 横版侧视，等比缩小会糊、放大糊满屏；
  ③ 授权不明。
- 结论：**拿来做描摹参考极有价值，直接贴进来不行**。

### 路线 B：80 招各做一套帧动画 → 不可行
1120 帧，且**这不是传奇的做法**（传奇只有十几套基础形状，靠组合出所有技能）。

### 路线 C（推荐，已实测）：基础形状 sprite 库 + 程序化组合
- **2 张**手绘/AI 位图（一小弯 + 一大弯月牙）+ 缩放/位移/交叉淡入/旋转 → 补出 14 帧动画。
- 质感与层次**碾压**纯矢量版。产能账：24 套基础形状 × 8~12 帧 ≈ **240 帧**覆盖 80 招。
- 技术接入点（已核实）：游戏内走 `drawOverlay → CV.renderCanvas(octx, fr.prims, ...)`，
  **不是**软件光栅 `rasterize` → 接位图只需在 `renderCanvas` 加 `k:'img'` 分支，**<20 行**。
- 配套：帧索引表 + 异步预加载 + **加载失败回退矢量**（否则素材没到位那招是空的）。

### 坑
- 素材异步加载后**必须触发重绘**（`im.onload = render`），否则 QS 带 f（暂停）时首帧是空的。
- 素材尺寸必须按我们 320×180 画布重新定（传奇是 800×600 场景）。
- AI 生成带背景色 + 右下角水印，要 flood fill 抠背景 + 裁水印。
- bash 里中文文件名传给 node/curl 易出问题，文件改名用 python。
- `SAMPLES` 是数组，用字符串 id 取要 `sampleById()`，否则 `undefined.draw` 抛错、整页渲染空白。

### 流水线（已跑通）

已出 5 张 sprite：blade_a / blade_b / fireball / seal / thunder（`legend-ref/sprites/`）。

### 相似度标尺（可验收）
真实传奇基准：hotPct .095/.051/.093、huePurity .46~.84、hueSpread ≤4、satMed ≥.55。
**hotPct 必须落在 0.05~0.12** —— 这是「像传奇」的量化锚点。

### 坑（都踩过）
- 抠图残留：水印区**必须 RGBA 置透明**，涂背景色无效（孤立矩形不与边缘连通，flood fill 吃不到）。
- 抠图边缘的半透明像素保留原背景色 → 会被误判成大片高光；
  修法：半透明处颜色换成最近实心邻居的颜色（MaxFilter 膨胀实心掩码 + composite）。
- 调色里改的 h/s 会被后面的 hsv 重算覆盖 —— 分流逻辑要放在重算之后。
- 自动调色**会压过头**：暗部染主色 >0.5 会丢掉橙黄渐层和白芯，先保守再微调。
- AI 生成复杂纹样（法阵的同心环+符文）缩到 300px 会糊 → 拆成「环 + 纹样」两个 sprite 叠加，或手绘。
