### 第 2 轮迭代：挥砍角度更大、要真砍到怪物身上

用户看完第一版的原话：**「这个效果不错 但是 我希望 剑挥舞的角度更大 要砍到 怪物身上，
现在更像是 靠在怪物身上」**。

定位到两个叠加原因：① 基线 `pose.a0/a1 = -2.45/-0.95` 只有 **86°**，收招角还在
水平线以上，剑尖全程在怪物头顶（f15 剑尖 y≈60，怪物躯干 y≈76~102），根本没切进去；
② 前冲 96px（低分辨率 48）让人冲到离怪物只剩 14px，视觉上就是贴上去。

改法（仍只动 `art-motion-preview.html`）：
- `T.a0 / T.a1` 变成**可拖的演出张角**，默认 `-160° → +20°`（**180° 横扫**），
  收招角压到水平线以下；`angAt()` 改读 T 而不是 `ART.pose`，
  **A 侧仍用基线 -2.45/-0.95 做对照**。两个角度做成度制滑块，现在共 9 个参数。
- `T.dash` 96 → 72，人和怪拉开距离。
- 新增 `bladeCut(hx,hy,tip,ex,ey)`：沿剑身采样 28 点求「剑身 ∩ 怪物躯干矩形」交点。
  切线 / 火花 / 白闪 / 冲击环全部钉在这个交点上，状态栏加「B 剑刃接触」实时显示
  切进剑身百分之几 —— 把「砍到了 / 只是贴着」变成可量化尺子。
- 新增第 13 个效果开关 `FX.cut`（剑刃切中火花）。
- 收势回抽：`angAt()` 在 `f > hit+hold+2` 后从 a1 插值回 `T.a0*0.55 ≈ -88°`

  `hit+hold+1`，末端剑尖高光点收势期不画，避免残光跟着回抽的剑乱跑。
- 切线寿命 `hit..hit+4`、`cut` 范围到 `hit+6`、冲击环仍 `hit..hit+6`，收势更干净。

## 80 招工程化路径衡量（只读调研，本轮未改代码）

用户确认破锋式「狠 ok」后问：一招招落实 80 招工作量是不是特别大、能不能自定义拼接、
还是我逐个实现。做了只读架构盘点（arts.js / game.js / artoverrides.js /
gen-artworkbench.js / art-workbench.html / tools 自检 / build.js），结论存档：

- **逐招手写不可取**：单招抽检页 ~1130 行 / 56KB，线性放大 ~7 万行，保守每招 60 行
  也 ~4800 行；更致命的是要往 `execArt` 塞 80 个招式 id 分支，推翻「运行时不认 id」
  的数据驱动架构，之后每改一招都要重跑生成器 + build + 两套路径 740/549 PASS。
- **现有底子够做组件化**：`execArt` 按 `a.fx` 分 14 支、0 处 id 硬编码；
  `arts.js` 已有 `fam(10) / slot(6) / fx(14)` 三条模板轴；`artShapeSpec` 16 画法原子、
  `swingAng` 16 运动原子本就参数化；`OVERRIDE_SAFE` 26 字段 + `artTiming()` +
  `buildPack()` + 工作台 `timeline / frames` 都是现成扩展点。
- **缺口**：没有独立「演出组件 / clip」字段；`game.js` 目前只消费
  `fxDelay / fxLife / timeline.fxStart / fxLen / windup / fps` 和 `frames` 系列，
  `timeline.total / hit / recover` 还没消费 —— 现在工作台填的 30 帧数据游戏里还不会按帧播，
  光靠现有面板拼不出完整演出。
- **推荐路线**：一次性做 `artClip` 组件引擎 + 按 `fam/fx/slot` 套模板 + 工作台组件拼接面板，
  约 300~400 行；65~70 招只填数据，真正要单独调的是离手 / 持续 / 召唤 / 特殊机制
  （boomerang 2 + orbit 2 + spin 3 + blink 1 + charge 1 + buff 插地等）约 10~15 招。
  落地要动 8 个文件（arts.js 可选 / artoverrides.js / gen-artworkbench.js /
  art-workbench.html / game.js / tools/arts.js / tools/art-unique.js / ART-WORKBENCH.md），
  最后 build.js；不碰平衡数值、不动 80/80 零重复字段。
- 用户「自定义拼接」可行，但不是从零自己写：覆盖表协议已经够，缺的是组件层 + 运行时消费；
  补齐后工作台勾选组件、拖时间轴、导出覆盖表就能直接试玩，不改 arts.js 基线、不破坏存档。
- 起步仍按用户习惯「直接给看」：先把破锋式这套 30 帧演出抽象成 6~8 个组件接进现有工作台，
  先让 1~3 招真跑起来，满意后再批量套模板。

## 旋风斩手持感回炉（用户反馈「不是武器在中间，看不到手」）

**用户原话**：「旋风斩是手拿着武器挥动 不是武器在中间 看不到手」。
这是第 2 批 `blade_4` 的返修，只改这一招，不碰其它三招（用户没审完不预先动下一批）。

**根因（放大画布才看清）**
1. 两把刀 `ang` / `ang+π` 严格 180° 对穿，加上手心半径只有 17px，
   视觉上就是「一根白色长杆横穿胸口」。
2. 手心轨道被贴地压扁 `fy=0.42`，手转到上下方向时离身体中心只剩 11px，缩回身体里。
3. 手臂 2.6px 且与袍子同色，末端手掌 3.1px 被白色刀身盖住。
4. 周边 18 片纯白刀刃半径 42~54px + 椭圆环 + 螺旋纹全压在脚下，糊住下半身。

**解法：抽 `twinRig()` 持握骨架，运行时绘制与逐招自检共用一份几何**
- `RIG_HR=26` / `RIG_FY=0.92` / `RIG_GAP=2.62`（≈150°）+ 一手抬 3px 一手落 3px。
  **关键口径**：贴地压扁 0.32 只作用于「挥出去的风 / 风纹 / 判定范围」，
  **不能连手臂一起压**，否则手又缩回中心。平面口径靠 `flat/squash/outer blades` 守住，
  不靠压扁手臂。
- 刀柄尾只回到手心内侧 3.5px，护手落在手心外 5px，刀身全部朝体外；
  手掌最后画、压在刀柄上（肤色圆点 + 手指横线 + 金色护手 + 深棕柄）。
- 屈肘折角 `-side*7 / -6.5`、袖子压深 `#d8c9ac`：否则白袖 + 白刃共线，
