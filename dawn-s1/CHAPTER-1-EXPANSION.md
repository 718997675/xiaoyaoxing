## 3. 地貌分区设计

地图从 96×72 扩到 144×104 后，按九宫格切成四块，中间是青云集：

```
┌─────────────────┬─────────────────┐
│  西荒石窟        │  北坡乱葬岗      │
│  (石窟/矿道)     │  (荒坟/阴气)     │
│  Lv 8-12        │  Lv 6-10        │
├─────────────────┼─────────────────┤
│  南岭竹海        │  青云集 (安全区)  │
│  (竹林/机关)     │  店铺/任务/打坐   │
│  Lv 3-7         │                 │
└─────────────────┴─────────────────┘
         ↓ 古洞入口在地图最北 (ALTAR)
```

**连通规则**（重要，别做成"四块孤岛"）：
- 每个区至少 **2 条**通道连回青云集（一主一窄），窄道放精英怪当"关卡守卫"
- 区与区之间至少 1 条捷径，玩家跑图不用绕回村子
- 所有通道宽度 ≥ 3 格，避免玩家卡在 1 格缝隙里

**主题调性**（**待确认**，见第 7 节）：
- 南岭竹海：清幽、机关陷阱、蛇与山魈、白天安全夜里凶
- 西荒石窟：狭窄、火把照明、石傀与火鸦、地形复杂
- 北坡乱葬岗：现有内容就地扩写（阴魂 / 鬼火 / 千年树妖）

### P2 · 营地生态（"两个营地要具备生态"）—— ✅ 已完成 2026-11-10

用户原话是"两个营地也要具备生态"。我的理解是**所有营地都该像个活的地方**，先做 2 个样板，再推广。

**生态 = 四件事**（缺一件就是"一堆怪站着"）：

1. **巡逻**：营地内固定路线，`patrol: [[x,y],...]`，到点转向
2. **警戒**：视野内发现玩家 → 吹哨（附近同伴一起 aggro）→ 追击 → 脱离距离后回营
3. **食物链**：食草妖（狐/蛇）被掠食者（山魈/熊）追，玩家可以"等它们打完再上"
4. **作息**：白天/夜间不同阵容（复用 `clock` 和 `phases`）

- [x] `camps` 每项加 `patrol` / `alert` / `night` / `lord`
- [x] 营地内部加"篝火 + 帐篷 + 哨塔"三类 props（视觉锚点，玩家一眼认出这是营地）
- [x] 夜间营地：火堆变亮、怪变凶、部分怪睡觉（可偷袭，配合已有的晨雾偷袭 ×1.5）
- [x] 3 个 tier3 精英营：加"营地首领"，打死才刷宝箱

**实际落地（和原计划的差异，写清楚免得后人困惑）**：

| 原计划 | 实际做法 | 为什么 |
|---|---|---|
| `patrol: [[x,y],...]` 手写 | 支持手写 `[[dx,dy],...]`（格偏移），也支持写数字自动摊椭圆环 | 12 个营地全手写容易写出"绕圈机器"，自动环 + 停顿反而自然 |
| 夜间"换一批怪" | **不换，同一批怪打盹** | 换批要处理"打到一半怪消失"的边界，风险高；打盹还能让玩家**夜里摸营偷袭睡着的山贼**，玩法更好 |
| tier3 精英营 | 不改 `tier`，用 `lord` 字段 | `tier` 决定掉落等级，改它会连带影响 `rollRarity`，收益不值这个风险 |
| "刷宝箱" | 首领死亡多掉 2 轮（银两 + 紫装） | 玩家要的是"这一下值钱"，不是"再去点一个箱子"，少一个交互读起来一样 |

**数值**：
- 营地 12 个，怪总数 87（含夜行 12 只 + 首领 3 只）
- 吹哨半径：巢穴类 90~110，哨营类 165~205（"哨营"就该比"巢穴"传得远）
- 夜行种 `NOCTURNAL`：阴魂 / 鬼火 / 阴鬼 / 影 / 火鸦 —— 正午睡
- 昼行种 `DIURNAL`：山贼 / 熊怪 / 石傀 / 狐 / 蛇 / 山魈 —— 子时睡
- 被打醒后 `wakeT = 25` 秒内不会再睡（否则偷袭能无限连）

**验收（实测，`tools/camps.js` 17 条）**：
- 站营地 300px 外观察 3 秒，4/5 只在动
- 打一只 → 同营地 4/4 只一起上
- 跑开 600px → 5 只全部脱战
- 山魈会盯上狐，狐 `panicT` 触发逃跑
- 正午 5 只阴物全睡、子时全醒；子时山贼全睡
- 打睡着的掉血且会醒
- 3 个首领（教头 / 蛇母 / 守墓人）都在，死亡多掉 4 件

**踩到的坑**：
- 篝火摆在营地正中且是实心的 → `tools/map.js` 的"营地可达"断言要改成检查**周围 3 格内有可站地块**，不能只测中心
- `e.sleep` 每帧按时辰重算 → 打醒后下一帧又睡回去，偷袭变无限连。加 `wakeT` 才解决
- 只有 `dc > 190`（离营地远）才脱战 → 被吹哨叫醒的怪会永远挂着 aggro。补 `d > 200`（离玩家远）
- 帐篷/哨塔原本用深灰，和踩秃的土色糊在一起 → 改成暖褐，并在地上加一圈篝火焦土

**招式引擎（这是这一批真正的产出）**

不写 `if (type === 'xxx')` 的招式分支。`monsters.js` 里写 `skills` 数组，`game.js` 里只有一个轮询器 + 一个分派器：

```js
// monsters.js
skills: [
  { name: '缠身',     fx: 'bind', cd: 8.5,  windup: 0.65, range: 128, bind: 1.3, dmg: 0.9 },
  { name: '毒雾',     fx: 'zone', cd: 10,   windup: 0.6,  range: 200, r: 44, life: 3.2, count: 3, color: C.jade2 },
  { name: '断竹横扫', fx: 'slam', cd: 5.5,  windup: 0.75, range: 80,  r: 78, dmg: 1.35 },
]
```

六种效果覆盖全部需求：

| fx | 含义 | 用在哪 |
|---|---|---|
| `slam` | 以自身为圆心的范围重击（有预警） | 断竹横扫 / 灼翼 / 拔刀斩 |
| `zone` | 在玩家脚下铺危险区（可留持续伤害） | 毒雾 / 布陷 / 地裂 |
| `rain` | 玩家周围随机撒 N 个落点 | 落石 / 火雨 |
| `summon` | 召唤同阵营小怪 | 唤傀 / 唤石 / 分身 / 镜像 |
| `bind` | 定身（只锁位移，不锁出招） | 缠身 |
| `fan` | 扇形弹幕 | 弩箭齐射 / 剑气 |

加一个新首领 = 在 `monsters.js` 写 6 行 `skills`，`game.js` 一行都不用动。

**地面危险区 `hazards`**

预警圈 → 引爆 / 持续伤害。要点：
- 画在 overlay 的 2D 层（`octx.arc`），不用精灵贴图 —— `RING_C` 是 12px 点阵，放大到 60px 会散成一圈碎方块，玩家读不出"这是范围"
- 外圈从 `r × 1.45` 收到 `r`，收完那一下就是伤害落点（"圈缩完就该闪"）
- 持续区引爆后留一团脉动色块，表示"这块地还在伤人"
- `resetWorld()` 与 `dgBuild()` 都要 `clearHazards()`，否则危险区跨局 / 跨层残留

**实际落地（和原计划的差异）**

| 原计划 | 实际做法 | 为什么 |
|---|---|---|
| 每首领一套 `attackPattern` 手写 | 统一 `skills` 表 + 六种 `fx` 分派 | 手写五套等于复制五遍"抬手→判定→特效"，改一处要改五处 |
| 首领放进营地 | 单独开**巢穴**（`dens`），半径 3 格清出空场 + 接一条小路 | 营地塞一只 500 血的家伙，玩家连清小怪的余地都没有 |
| 无面剑客另起一张图 | 岩魈倒下后**原地接棒**，并计入清层条件 | 古洞第三层已经是"终局房"，再开一张图是浪费；接棒还能做成"石胎碎了，里面那道剑痕才露出来" |
| `unique: true` 随机生成 | 名字写死 + 专属词缀（`id: 'uniq'`） | 随机名字记不住"从谁身上掉的"；专属词缀还参与不了重铸 |
| 按 `e.type === 'boss'` 判断首领 | 统一 `e.boss`（`behavior === 'boss'`） | 以前加一个首领要改七八处判断（血条 / 击退 / 掉落档位 / 小地图） |

**数值**：
- 巢穴 4 个：青鳞潭 / 废弃机坊 / 石母洞 / 火鸦绝壁，各接一条小路
- 招式冷却**各自独立计时**（`e.skillCds[]`），全局间隔 `skillGap` 0.7~1.2 秒

### P4 · NPC 与任务 —— ✅ 已完成 2026-11-10

**任务系统从零建**。原来只有侠名、传闻、店铺对话三样散装的东西，没有任何"你接了一件事"的概念。

**实际结构（和计划的差异）**：

| 原计划 | 实际做法 | 为什么 |
|---|---|---|

## 5. 技术要点与已知坑

### 5.1 地图变大要同步改的地方

| 位置 | 为什么要改 |
|---|---|
| `MAPW` / `MAPH` 常数 | 所有 `y * MAPW + x` 的索引都依赖它 |
| `solid` / `tiles` 数组初始化 | 大小 = MAPW×MAPH |
| 地图生成循环里的散点数量 | 写死的 90 / 320 要按面积比放大，否则大图会稀 |
| 小地图绘制 | 现在按 96×72 缩放，要改成按实际尺寸比例 |
| 相机 clamp | `Math.min(MAPW*TILE - LW, ...)` 已参数化，应该自动生效，但要验 |
| `nearClear()` / `inVillage()` | 营地与村庄的排斥半径要重新算，否则新营地会压到建筑 |

### 5.2 存档兼容（必须处理）

旧存档的 `x/y` 在新地图上可能落在墙里或地图外：

```js
// load() 里，Object.assign 之后
if (!canStand(player.x, player.y)) {
  player.x = SPAWN.x; player.y = SPAWN.y;
  msg('地脉变动，已送回青云集', C.jade3);
}
```

### 5.3 性能

- 地图生成是同步的，144×104 约 2.2 倍格数，实测若 > 300ms 需要分帧
- 渲染只画视口内（`camera` 裁剪），地图变大不影响帧率，但要确认没有全图遍历的每帧循环
- `lightSources` 是全图数组 —— 夜里逐光源算光照，营地从 6 涨到 12 会翻倍，注意 `drawDayNight` 的耗时

### 5.4 测试怎么写

现有 `devtest.js` 的断言风格：
```js
T('名字', 条件, '实测值');
```
新功能照这个写，重点覆盖：
- 四区连通性（洪水填充）
- 每个营地的怪都能刷出来
- 每个首领能被打死
- 每条任务能完成
- 存档往返（存→读→状态一致）

## 9.8 P12-D · 全表零重复（2026-11-11）

### 9.8.1 起因：P12-C 的验收口径不够严

用户 2026-11-11 提的要求原话：**「现在验证所有武器招数是否有重复，我不允许有任何重复的点，
否则就没有意义了」**。这一刀砍在 P12-C 的验收口径上。

P12-C 查重查的是「**同一把兵器内** 8 招的四签名不重复」（`tools/arts.js` §1.1 / §1.3）。
全表 80 招之间从来没查过。用一次性探针把整表扫了一遍，结论如下：

| 维度 | 不同值 | 重复组 / 多余条目 |
|---|---|---|
| 招式名 / 描述 | 80 / 80 | 无 |
| 完整五签名 | 80 / 80 | 无 |
| 机制全字段 | 80 / 80 | 无 |
| **刀光形状 `shape`** | 19 | 18 组 / 61 |
| **动作 `pose.mode`** | 18 | 17 组 / 62 |
| **色彩 `color`** | 16 | 12 组 / 64 |
| **声音对 `snd/hitSnd`** | 40 | 21 组 / 40 |

更要命的是**整招撞车**，不是"共享池"这种可解释的重复：

- 三签名撞车 4 组：`sword_1≈chain_1`、`sword_2≈chain_2`、`staff_7≈chain_7`、`dual_2≈fan_2`
- 四签名撞车 3 组：上面三类连起手音都一样（`qi` / `slash` / `levelup`）
- 动作全参数撞车 5 组：`sword_5≈staff_5≈chain_5`、`hammer_8≈chain_8`、`hammer_2≈chain_4` ……

也就是说：链 / 扇这 16 招里有一半是把剑 / 棍 / 双刃的招式改了名字和数字，连刀光长相、
动作曲线、配色和音色都照抄。玩家切到链以后看到的「锁喉」，和剑的「破锋式」几乎一样。

### 9.8.2 口径：复合变体 · 全表唯一

四个池（14 原语 / 19 形 / 20 式 / 17 音）**一个不加**。它们是渲染与合成的**原型**，
重复原型不等于招式重复 —— 真正要保证的是「玩家能分辨出这是两招」。

于是每招在四个感知维度上各拿一个**全表唯一的表现实例**：

| 维度 | 签名 | 实现 |
|---|---|---|
| 形状 | `shape@shv` | 新字段 `shv`（1~9，同一基础形内递增）。`artSwingFx` 在 19 个分支跑完之后统一后处理：半径 / 长度 / 线宽 ×(1+0.055k)，扫角按半径同比拉开 |
| 动作 | `pose` 全参数 | `mode/a0/a1/dur/ease` 五项一起算签名；撞车的把 `a1` 微调 0.02（角度影响 < 1.2°，连拍 7° 门槛不受影响） |
| 色彩 | `color` 主副色对 | 保住每组第一次出现，其余从 20 色锁定板重排成互不相同的一对（主色亮、副色暗，同族优先） |
| 声音 | `snd/hitSnd` 对 | 保住每组第一次出现，其余改命中音（必要时改起手音），保证**同兵器内 8 个起手音、8 个命中音也各自不重复**（§1.1 的老断言继续成立） |

> **为什么不是「80 个互不相同的刀光画法 + 160 个独立音色」**：那要新画 61 种刀光、
> 新合成 143 个音效，是一次内容工程而不是验收整改；而且 80 招各有专属画法会把这个
> 像素武的画面语言拆散。复合变体是「原型共享、实例不重」—— 玩家看到的确实是两招。
