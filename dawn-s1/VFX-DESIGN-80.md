# 80 招特效视觉语言设计（路径 A · 设计层）

> 2026-11-14 · 依据「玄幻打斗」特效层方法论，翻译到本项目的俯视 2D 像素 ARPG。
> 配套产物：`tools/gen-vfx-overrides.js`（生成器）、`art-overrides.sample.json`（10 招样板）、
> `art-overrides.vfx80.json`（80 招全量，待确认后启用）。
> **本轮只落设计层与节奏层，一行产品代码都没改。**

---

## 1. 先划边界：什么能动，什么不能动

项目在 P12-D/E 已经刻意把 80 招做成「全表零重复」：`shape` / `pose.mode` / `color` 对 /
`snd` 对 / `hitSnd` / `shv` 各自都是 80 个互不重复的值，`tools/art-unique.js` 会卡死任何撞车。
这是上一阶段专门做的「去同质化」工程，不是待修的 bug。

所以路径 A 的设计**不是推翻它，而是给这些随机的唯一值补上语义**：

| 字段 | 本轮 | 原因 |
|---|---|---|
| `timeline`（30fps `fxStart` / `fxLen`） | ✅ 本轮落表 | 全新维度，不碰任何零重复字段；`artoverrides.js` 白名单内 |
| `shape` / `pose` / `color` / `snd` / `hitSnd` / `shv` | ❌ 保持基线 | 改了必然撞 `tools/art-unique.js`，且会让 553 条回归失去基线 |
| `desc` | ❌ 不改 | 现有文案写着机制（如「无视三成防御」），覆盖会丢玩家信息 |
| `frames` PNG 序列帧 | ⏸ 留给路径 B | 要先出图，本轮不做素材 |

**家族配色写进本文档作为后续换色规范，暂不落覆盖表。** 等要动色时，得先决定「零重复」与
「家族统一色」哪个优先——两者直接冲突，不能闷头改。

## 2. 档位：克制为主，只在高潮切爆发

俯视 2D 一屏会同时出现玩家、多个敌手、掉落与地形特效，按「玄幻打斗」的量级判定，
**默认必须是克制暗场模式**（特效占画面 15–40%，单色主导）。全程满屏等于视觉疲劳。

- 十类兵器每类 8 招，只有 `prof === 10` 的压轴招切**爆发档**（`fxStart 8 / fxLen 22`）。
- 档位切换本身就是高潮信号：玩家练到满专精，招式突然变长、变慢、余波给足。
- 其余 70 招全部克制，`fxLen` 控制在 5–17 帧（0.17–0.57 秒）。

压轴招在各家族里是 `id` 尾数为 7 的那一招（解锁等级序列 1/2/3/5/6/8/**10**/4）。

## 3. 三支柱在俯视像素里的翻译

| 原方法论 | 本项目落地 |
|---|---|
| **暗场发光**：背景压暗，只让术法发光 | 项目已有昼夜暗罩与洞内恒暗 `rgba(7,8,15,0.84)`；特效在酉/子时与地宫里天然更"实"。白昼不加额外压暗，避免和昼夜系统打架 |
| **轴向光**：每次冲击沿一条主光轴 | 由 `shape` 的刀光几何承担（基线已定），本轮不动；`fxStart` 决定光刃沿轴射出的那一帧 |
| **爆点对位**：特效本体 0.3–1.5s，硬切 + 鼓点 | 命中白心由基线 `color[0]`（多为 `paper3`/`white`）承担；`fxLen` 的后段由 `game.js` 用 `g.t / g.max` 做衰减，即⑤余波 |

`artTiming()` 的换算链已核实：`timeline.fxStart` → 刀光 `delay`，`fxLen` → `t / max` 寿命
（`game.js:3583` 附近）。所以节奏层**只靠 timeline 就能真实生效**，不需要改运行时。

## 4. 七色盘 → 项目 24 色锁定板 `C`

「玄幻打斗」给的七色盘是写实视频色值，项目是 24 色程序化点阵，必须做映射：

| 方法论色 | 值 | 项目 `C` 近似 | 用在哪类兵器 |
|---|---|---|---|
| 竹青 | `#2FD08A` | `jade3 #9BD4CC` / `jade2 #5FA8A0` | 剑、枪、扇（正道清气） |
| 幽蓝 | `#3A7BFF` | `ink3 #4A5568`（项目无纯蓝，取最冷的中性） | 双刃、暗器 |
| 电紫 | `#A45CFF` | `pur2 #8A6FC4` / `pur3 #C0A8E0` | 法、链 |
| 符金 | `#FFC83D` | `gold2 #D9A441` / `gold3 #F2D089` | 杖、锤、扇（压轴） |
| 赤血 | `#E0242B` | `red2 #C8453B` / `red3 #E8806F` | 刀、锤 |
| 冰晶 | `#7FE3FF` | `paper3 #E8DFC8`（冷白，项目无青蓝高光） | 法（副色）、剑（副色） |
| 暗场底 | `#0B0D14` | `ink1 #12161F` | 底色，不进 `color` 数组 |

配色铁律照搬但按项目改写：**每招主色 ≤ 2**（`color` 数组正好两格）+ 底色 `ink1`；
白心只留给命中瞬间；同一场战斗不许出现两个金色主导的招式（所以金色只给杖/锤/扇）。

## 5. 五阶段 → 30fps 帧数

视频里的 6–10 秒五阶段，压进一次招式的 0.3–1.6 秒：

| 阶段 | 视频 | 游戏里的对应 | 落在哪 |
|---|---|---|---|
| ① 起势 | 1.5–2s | 挥兵器的前摇 | `pose`（基线已有，不动） |
| ② 蓄能 | 0.5–1s | 光在剑尖汇聚 | `fxStart` 之前的 1–9 帧 |
| ③ 释放 | 0.3–0.6s | 光刃沿轴射出 | `fxStart` 那一帧 → `fxLen` 前段 |
| ④ 命中 | 0.3–0.5s | 白心 2–3 帧 | 基线 `color[0]`，不动 |
| ⑤ 余波 | 1.5–3s | 光点淡出 | `fxLen` 后段（`g.t/g.max` 衰减） |

功能位基线（帧）：

| 功能位 | `fxStart` | `fxLen` | 意图 |
|---|---:|---:|---|
| 单体·连击 `dmg` | 2 | 8 | 快切密集，打得爽 |
| 清场 `aoe` | 4 | 12 | 稍蓄力，覆盖面大 |
| 位移 `move` | 1 | 6 | 极快，几乎无前摇 |
| 控制 `ctrl` | 5 | 10 | 前摇明显，给出预判 |
| 增益 `buff` | 7 | 12 | 最慢，起势感 |
| 特色 `special` | 3 | 12 | 居中 |
| **压轴爆发** | 8 | 22 | 全表唯一的高密度档 |

再叠加家族系数 + 按 `id` 序号的确定性 ±1~2 帧错位。为什么加错位：同家族同功能位常有两招
（如 `sword_1` 破锋式 / `sword_2` 连环刺），节奏完全一样就连招像复制粘贴——对应方法论里
「残影必须有位移 + 透明度渐变」的禁忌，在 2D 里就是帧错位。压轴招不抖，保住统一的压轴感。

## 6. 怎么用（不改代码，随时可回滚）

```bash
cd dawn-s1
# 改了规则就重生成两个覆盖表 + 表格片段
node --experimental-default-type=module tools/gen-vfx-overrides.js
```

1. 双击 `art-workbench.html`（或线上 `/art-workbench.html`）
2. 导入 `art-overrides.sample.json` → 「写入试玩」，进游戏看 10 招的节奏差异
3. 过目后再导入 `art-overrides.vfx80.json` 铺满 80 招
4. 不满意就点「清空覆盖表」，`localStorage` 一删即回到基线，`arts.js` 一个字节没动

> 覆盖表只写 `timeline`，工作台 UI 里可能看不到时间轴细节，判断以游戏内实际表现为准。

## 7. 自检与禁忌

生成器每次运行会做四件事，任一不过就 `exit 1`：

1. 所有 `id` 必须存在于 `ARTS`，总数必须 80
2. 所有字段必须在 `OVERRIDE_SAFE` 白名单内，且不含 `shape/pose/color/snd/hitSnd/shv/id/fam/slot/prof`
3. 每条经 `artTiming()` 换算后 `delay > 0 && life > 0`
4. 同家族 + 同功能位内，`fxStart/fxLen` 组合不许撞车

并且做了两条**反向验证**（故意塞越界字段、故意造组内重复），确认自检器真会报红，不是永远绿的摆设。

禁忌清单（照方法论改写）：剑气不许做粗做钝做慢；不许全表都在炸；命中必须有白心；
残影不许纯复制；不许把翠玉绿当主角能量色；不许在成品提示词里写「很炫」这类不可拍摄的词。
