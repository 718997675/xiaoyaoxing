# 逍遥行 · 技能体系与剧情扩充方案

> 需求原话：「每种武器 分别可装配8种主动技能，每种技能都有各自的特效、特色、伤害机制、要设计科学平衡，
> 这里你帮我想想要不要加入职业系统」「剧情要扩充，要有代入感，剧情文本也要扩充」
>
> 本文是**交接文档**，接 `CHAPTER-1-EXPANSION.md` 之后做。

## 一句话结论（后面几万字都可以不看，这句要看）

**不做职业系统。整个成长拆成三层，全部挂在兵器上：**

| 层 | 承载 | 给玩家什么 | 美术成本 |
|---|---|---|---|
| 成长层 | 兵器专精 0→10 级 | 长期目标 | 0 |
| 构筑层 | **心法** 一主二辅 | RPG 构筑（540 种组合） | 0 |
| 动作层 | 八兵器 × 八技能（64 个） | ACT 爽感与技巧 | 复用现有 |

**为什么不做职业**：职业必然锁武器，而掉落的八类兵器是这个游戏的核心奖励 ——
锁了武器，捡到的紫装七成变废品，掉落循环直接断掉。而且八个职业要八套动作帧，
像素风下这是几百帧的成本。心法零动画、零贴图，却能给出比八职业多得多的构筑深度。

**章节**：一、为什么不做职业 ｜ 二、64 个武器技能 ｜ 三、心法系统 ｜ 四、剧情 ｜ 五、施工批次 ｜ 六、工作量

## 一、先回答那个问题：要不要做职业系统

**结论：不做传统职业，改做「兵器专精」。**

### 为什么不做职业

| 理由 | 说明 |
|---|---|
| **职责重复** | 八类兵器已经在承担"职业"的玩法分化职能了 —— 换兵器就是换玩法。再加一层职业是同一个抽象做两遍。 |
| **和核心循环打架** | 这游戏的核心是"掉落驱动刷宝"。打出把传世宝刀，却因为你是"剑客"不能用的挫败感，比数值不平衡严重得多。 |
| **会锁死构筑** | 职业的代价是自由度。玩家想试"锤 + 法杖"的怪组合时，职业系统会说不行。 |

### 为什么专精更好

职业真正提供的价值是**身份认同**和**成长感**，这两件事不需要靠"锁死"来实现：

```js
player.prof = { sword: 0, blade: 0, spear: 0, staff: 0, dual: 0, hammer: 0, mage: 0, dart: 0 }
// 0~10 级。用某类兵器造成伤害就涨，涨得比击杀慢，逼玩家真的"练"。
```

- **8 个技能按专精等级解锁**（1/2/3/4/5/6/8/10 级各解锁一个）
- **换兵器不损失进度**，但新兵器要从 1 级练起 —— 这就是"转行"的自然成本，不需要惩罚
- **称号系统**：某兵器专精满级给称号（剑→「剑心通明」、锤→「开山」），挂在侠名旁边
- **门派声望**（可选）：专精等级影响某些 NPC 的态度，这是"身份"的叙事层表达

> 一句话：**用"练什么像什么"替代"选什么是什么"。** 玩家仍然是自由的，但玩久了自然有身份。

## 二、64 个技能的设计框架

### 2.1 功能位（每个武器都按这 6 类铺，保证有搭配而不是 8 个伤害技）

| 位 | 作用 | 每武器数量 |
|---|---|---|
| ① 主力输出 | 高伤单体 / 短 CD | 2 |
| ② 清场 | AOE / 中 CD | 2 |
| ③ 位移 | 突进 / 后撤 / 瞬移 | 1 |
| ④ 控制 | 定身 / 击退 / 减速 / 眩晕 | 1 |
| ⑤ 增益 | 自身 buff（攻速 / 暴击 / 护盾 / 减伤） | 1 |
| ⑥ 特色 | 该武器独有的机制 | 1 |

### 2.2 平衡公式（先定规则，再填数值）

以"同等级普攻 DPS = 100"为基准：

```
技能等效 DPS = 100 × 系数
系数按 CD 分档： 3s→1.6   6s→2.4   10s→3.4   20s→5.0   30s→6.5
真气消耗      = CD(秒) × 1.2        （真气上限 60~150）
```

**总输出校验（重要）**：8 个技能全开打满一轮，DPS 不得超过普攻的 **2.8 倍**。
超过就说明普攻没意义了，玩家会变成"等 CD"游戏。

**生存校验**：任何"增益类"技能，其收益不得超过同等 CD 输出技能的 70%。
（护盾 / 减伤 给太高会让玩家只带增益技）

### 2.4 装配规则

- **6 个招式槽**（`ART_SLOTS`），键位 **`1`~`6`**，画在主技能栏上方一排
- 只能装配**当前手持兵器**的招式（换兵器自动切技能组：不属于新兵器的格子会被清空，
  同兵器内部的手动编排保留）
- 技能解锁看该兵器专精等级，不是道行点 —— 道行点继续管被动树
- 装配界面：道行面板加一个「招式」页签（`T` 打开，页签切换）

> **与原计划的差异（P5 实施时改的）**：原稿写的是 8 槽 / 只能带 6 个 / 键位 J·K·L·H·U·I。
> 实际做的时候发现 `J`（普攻）`K`（剑气）`L`（剑舞）`H`（天雷诀）全被老系统占着，
> 硬抢会破坏已经稳定的手感。改成 **6 槽 + 数字键**：数字键是"格子序号"，
> 跟招式页里的装配格一一对应，比塞进动作键区更直观，也不用改老键位。

> **与原计划的差异（P6 实施时改的）**：原稿的"8 槽 / 带 6 个"是在 P5 只有 16 招时的写法
> —— 八个功能位各配一招，玩家挑六个带上。P6 补到 64 招之后，这套读法反而误导：
> 玩家面对的不再是"八招里挑六招"，而是**"八种功能位各有多招，从八把兵器里凑六格"**。
> 现在每招都带一个**功能位标签**（输出 / 清场 / 位移 / 控制 / 增益 / 特色），
> 共 64 招 = 输出 16 · 清场 16 · 位移 8 · 控制 8 · 增益 8 · 特色 8。
> 装配界面按功能位分组显示，玩家一眼能看出"自己缺哪一类"。

**装配交互（P9 重做，取代 P6 的"先点格再点招"）**

P6 的模型是"先点上方格子选中它，再点下方招式装入"。实装之后那个中间态很碍事：
忘了点格子就只装进第 0 格，装完还得回头确认自己刚才点的是哪一格。
P9 把它拆成三个**一步到位**的动作，中间态整个删掉：

1. **拖招式卡到某一格** = 装到那格；格里有招就**互换**，谁也不会被挤没
2. **点招式卡** = 装进第一个空格；已装则卸下
3. **点格子** = 直接卸下
4. 六格全满且没指定格 → 提示"把招式拖到想替换的那一格上"，
   **不替玩家决定**（早期版本会无声顶掉第 0 格，把玩家排好的顺序打乱，已废弃）

**布局**：「剑匣 + 招式谱」两栏。左栏六格竖排（汉字格号 壹~陆 + 招名 + 功能位 + 功能位色条），
右栏是按功能位分组的**两列卡片网格**。左栏看"我带了什么"，右栏看"我还能带什么"，
同屏对照，不用在脑子里记顺序。已上阵的卡片显示所在格号（壹/贰/…），
和左栏一一对上。

**触屏**：拖拽要求长按 150ms 才启动 —— 否则手指落在卡片上往下划会被当成拖拽，
招式库在手机上根本滚不动。鼠标没这个歧义，按下即可拖。

**手动优先**：`player.loadoutManual` 标记玩家动过装配格。一旦动过，
专精升级触发的 `autoLoadout` 就不再自动补满空格 —— 玩家自己卸下的招不会被悄悄塞回来。
新悟到的招（`autoEquipNew`）在六格满时自动顶掉**专精最低**的那一格；
若玩家手动排过，则不顶，改为在提示行里告知。

### 2.5 实现要点

```js
// arts.js（已落地）
export const ARTS = {
  sword_1: { id:'sword_1', fam:'sword', slot:'dmg', name:'破锋式', prof:1,
             cd:4, cost:4.8, fx:'melee', reach:40, arc:1.2, mul:6.6, kb:9, pierceDef:0.3,
             desc:'一剑直取，无视三成防御。' },
  // ...
};
export const PROF_NEED = [2,6,14,26,42,62,88,118,156,200];  // 到第 n 级所需累计击杀
```

- **效果原语有十种**（P5 六种 + P6 四种）：
  `melee` / `proj` / `spin` / `orbit` / `blink` / `bolt`（P5）
  ＋ `dash`（位移）/ `buff`（增益）/ `zone`（地面区域）/ `pull`（拉拽）（P6）。
  `execArt()` 一个分派器 —— 但**P6 之后"加一招只写数据不改运行时"这句不再成立**：
  设计表里的位移 / 增益 / 区域 / 拉拽硬塞进原六种只会变成换皮。
  **原语清单是数据层与运行时的共同契约**：`arts.js` 的 `ART_FX` 和
  `game.js` 的 `execArt()` 分支必须一起改。
- 修饰字段复用：`pierceDef`（破防）/ `status`（挂状态）/ `launch`（击飞）/
  `centerBonus`（环身技中心双倍）/ `lifeOnHit`（每击回血）/ `reflect`（格挡反弹）。
  P6 新增：`ramp`（逐段递增）/ `critAdd` `critLast`（必暴）/`kbLast`（末段击退）/
  `back`（反手打）/ `backBonus`（背后加成）/ `randomTargets`（乱斩随机目标）/
  `ring`（环形齐射）/ `splash`（弹体溅射）/ `chain`（链式，每跳衰减）/
  `fall`（落雷）/ `forceCrit` `nextDmg` `iframe` `stealth` `shieldPct`（位移附带）/
  `def`（增益数值）。
- 特效复用 `slashGhosts` 通道（普攻刀光也在用），**不要**在 `update()` 里直接画。
- 新状态：`bleed` / `burn` / `poison` / `freeze` / `stun` / `slow` / `break` / `launch`。
  DoT 不走 `hitEnemy` —— 那会触发顿帧、连击、火花、击退，中毒的怪会让屏幕抖个不停。
- **地面区域**（P6）：`zones` 与首领招式的 `hazards` 分开存，互不干扰。
  区域伤害走 `dealDot`（不走 `hitEnemy`），否则每 0.4 秒一次顿帧会让整块屏幕抖个不停。
  多分片区域（地裂 4 片）伤害要**摊分**（每片 `mul / 4`），否则"四道地裂"是 4 倍伤害。
- **平衡口径**：统一走 `arts.js` 的 `artPower(a)`（"等效总倍率"），
  文档和自检都调它，不要各算各的。
  注意 `status.pct` **只有 DoT**（`bleed` / `burn` / `poison`）能折进总倍率；
  减速的 pct 是降速比例、定身无 pct、破甲的 pct 是破防比例 —— 折进去会算出假账
  （断筋一度被算成 15 倍伤害）。
- 存档：`player.prof`、`player.loadout`、`player.loadoutManual`。
  增益 / 地面区域**不进存档**（重进游戏清空）。

**P6 顺手改掉的一个心法 bug：焚心的真气口径**

P5.5 的焚心是"每次命中额外耗 5 真气（净 -2）"。P6 六招同开之后，
**招式的多段命中把按命中收的气放大到把真气池抽干** ——
实测"焚心 + 六招满配"的 DPS 只有裸装的 **33%**（招式根本放不出来，只剩普攻在砍），
心法自检"没有组合比裸装弱一半以上"直接挂掉。

改成**按挥击收气**：普攻挥击带编号 `player.mFxSeq`（`info.basic`），
招式命中不带编号 → 招式不参与焚心的真气结算；一次挥击命中多只怪只收一次气。
改完焚心 + 六招满配的 DPS 回到裸装的 **97%**，代价仍是"吃真气"。

> **教训：按次数收的代价，要先确认"次数"是被玩家选择的还是被构筑放大的。**

**踩坑**（详见 `HANDOFF.md` §6）：
自检脚本把伤害基线采在施法**之后**（近战 / 位移 / 拉拽是瞬间结算的，量出来永远是 0）；
位移走廊是**沿面朝方向的直线**，木桩放斜角就打不中；
`bash grep` 在本机返回空结果（与文件内容无关），一律用专用 Grep 工具。

## 三、心法系统（构筑层）

> 这一章是 2026-11-10 追加的。前面已经定案：**不做职业，武器技能做动作层，心法做构筑层。**
> 心法的存在意义只有一个 —— 让八把兵器不至于"谁数值高就用谁"。它必须**零动画、零新贴图**，
> 纯数据 + 纯 UI，这样才能和地图扩容、剧情扩容并行做而不互相拖。

### 3.1 为什么是"心法"而不是"天赋树"

现有的 `NODES` 被动树（道行点）已经在做"通用数值成长"了。心法不能再做一遍同样的事，否则玩家会觉得是两套重复的东西。

区别在这里：

| | 道行点被动树（已有） | 心法（新增） |
|---|---|---|
| 性质 | 线性成长，人人都会点满 | 互斥选择，一局只能带 3 条 |
| 给什么 | +攻 +血 +暴击 这类纯数值 | **改变打法**的机制 |
| 什么时候换 | 几乎不换 | 打不同的首领要换 |
| 数量 | 一棵树 | 12 主 + 10 辅 |

一句话：被动树让你变强，心法让你**换一种强法**。

### 3.2 槽位结构：一主二辅

```
┌─────────────┐
│  主心法 ×1   │  ← 12 选 1，每条带一个"机制"，不是纯数值
├──────┬──────┤
│ 辅心法│ 辅心法│  ← 10 选 2，纯数值/小被动
└──────┴──────┘
```

组合数 **12 × C(10,2) = 12 × 45 = 540 种**。比八职业的 8 种多两个数量级，美术成本是 0。

主心法**互斥**——只能带一条。这条规则是整个系统成立的关键：如果允许叠两条，玩家一定会去找"哪两条乘起来最爆"，最后收敛成一个答案；互斥逼你在"这一趟要什么"上做选择。

### 3.3 十二条主心法（机制向）

数值都是初版，实现后要用脚本跑一遍 DPS，允许 ±20% 调整。

| # | 心法 | 机制 | 数值 | 适合 |
|---|---|---|---|---|
| 1 | **破军** | 对满血目标增伤，对残血目标减伤 | 满血 +25% / 半血以下 -10% | 高爆发、暗器、锤 |
| 2 | **归元** | 脱战 3 秒后持续回血 | 每秒 4% 最大气血 | 长线探索、枪、棍 |
| 3 | **追命** | 连续命中同一目标递增 | 每次 +6%，上限 +60%，换目标清零 | 双刀、剑（多段） |
| 4 | **血河** | 吸血，但上限换 | 伤害 8% 转气血 / 最大气血 -15% | 刀、锤（硬碰硬） |
| 5 | **铁衣** | 受击后短时减伤，可叠 | 受击后 2 秒减伤 30%，叠 2 层 | 近战、棍 |
| 6 | **疾风** | 移速换闪避后爆发 | 移速 +12%；闪避后 1.5 秒内下一击 +40% | 双刀、暗器 |
| 7 | **焚心** | 攻击附带灼烧，但吃真气 | 3 秒 DoT（每秒 30% 攻击力），每次攻击 -2 真气 | 法杖、刀 |
| 8 | **寒潭** | 减速流 | 15% 概率减速 40%/2 秒；对被减速目标 +20% | 法杖、枪 |
| 9 | **空明** | 真气流 | 真气上限 +40%、回复 +50%，技能伤害 -15% | 法杖、暗器 |
| 10 | **藏锋** | 蓄力流 | 不出招每秒蓄 1 层「锋」（上限 5），出招每层 +12% | 锤、刀（一击流） |
| 11 | **卸力** | 挨打换真气 | 受击时 20% 伤害转真气 | 棍、剑（防反） |
| 12 | **无常** | 暴击流 | 暴击 +15%、暴伤 -30%；暴击 25% 概率重置一个技能 CD | 剑、双刀 |

**设计约束（必须守住）**：

1. 每条主心法都要有**代价**。没有代价的那条会变成所有人的默认答案。
2. 伤害类加成全部走**同一个加法区**，不要出现"乘算叠乘算"。任何单一来源的伤害加成上限 **40%**。
3. 主心法不能只对某一类兵器有效。破军配暗器强、配棍弱，可以；破军只有暗器能用，不行 —— 那就变回职业了。

|---|---|---|
| 1 | 明目 | 暴击率 +8% |
| 2 | 沉肩 | 受击硬直 -20%，击退抗性 +12% |
| 3 | 长息 | 真气回复 +25% |
| 4 | 磨锋 | 攻击力 +6% |
| 5 | 轻身 | 移速 +8% |
| 6 | 厚土 | 最大气血 +15% |
| 7 | 锐金 | 破防 +10% |
| 8 | 静水 | 技能冷却 -10% |
| 9 | 贪狼 | 银两掉落 +20% |
| 10 | 拾遗 | 装备掉落率 +8% |

辅心法里刻意放了 **贪狼 / 拾遗** 两条"不打架"的：有些玩家就是喜欢刷，不该逼他全点战斗。

### 3.5 获取与解锁

不做新货币。**学一次永久拥有，之后随便装。**

| 来源 | 给什么 |
|---|---|
| 游方道人（新 NPC，游走于青云集与竹海） | 辅心法，银两购买，随侠名打折 |
| 首领首杀 | 主心法（每个首领固定掉一条，8 个首领 → 8 条） |
| 主线节点 | 剩余 4 条主心法 |
| 藏经阁残卷（环境叙事物件） | 随机 1 条已学心法的"注解"，+1 级强化（上限 3 级） |

> 主心法**不能全靠买**。它是构筑的核心，必须让玩家觉得"这条是我打下来的"。
> 首领首杀固定掉，是最省事也最有仪式感的做法。

**生效方式**：不新写一套战斗逻辑，把心法折进已有的 `stats()` 里。

```js
function mantraMod(loadout, owned) {
  const m = emptyMod();   // 15 个字段，全是加法语义
  const all = [loadout.main, ...loadout.sub].filter(Boolean);
  for (const id of all) {
    const a = MANTRAS[id], k = lvMul(owned[id] || 1);
    if (a.mods) for (const key in a.mods) m[key] += a.mods[key] * k;
  }
  return m;
}
```

- **机制类**（破军 / 追命 / 藏锋 / 卸力 / 无常）在 `hitEnemy()` / `damagePlayer()` 里各插一个钩子，不改主流程
- **状态类**（焚心 / 寒潭）复用已有 `burn` / `slow` 状态，不新增状态机
- 存档：`player.mantras`、`player.mantrasOwned`，读档时校验 id 是否还在 `MANTRAS` 里（删过的心法要能优雅降级）

#### 平衡实测

`tools/mantras.js` 第 10 节：200 组随机组合（固定随机种子），同一把剑、同一根 20 万血木桩、
8 秒窗口、正午、关顿帧、`Math.random` 换成固定序列。

| 指标 | 数值 |
|---|---|
| P50 | 3433 |
| P95 | 4268 |
| **P95 / P50** | **1.24**（要求 ≤ 1.35） |
| 裸装（不带心法） | 3287 |
| 最强组合 | 追命 + 磨锋 + 轻身 4666 |
| 最弱组合 | 空明 + 贪狼 + 锐金 3058 |
| 同组合连跑五次极差 | 3%（要求 ≤ 20%） |

连跑两次输出逐位一致。**绝对 DPS 只有在钉死随机源之后才有意义** ——
`equipFam()` 内部是 `makeGear(..., Math.random, ...)`，兵器词条随机滚，
不钉种子时整条基线能差四成（连跑四次 P50 = 2943 / 3856 / 4208 / 3331）。
比值不受影响（同一次运行内自己比自己），但"改完数值有没有用"只能看绝对值。

**测这组数踩了 6 个坑**（都写进 `HANDOFF.md` §6 了）：
命中回 3 真气把焚心的代价抵消、寒潭概率型代价在实战里不存在、
`hitstop` 冻结整帧让攻速不稳（同组合能差 55%）、
升级累积 `atkBase`、野怪刷新与时辰漂移（26 分钟游戏时间足够跨昼夜）、
`equipFam()` 随机词条让绝对值不可比。

### 4.3 叙事骨架（三区三幕 + 终章）

地图定案走**方案 A**（详见 `CHAPTER-1-EXPANSION.md` 第 7 节）。叙事完全按新地理由东南向西北螺旋推进，
**三区各守一件东西**，凑齐才能开最北的古洞 —— 这样三个区域不是"顺路打怪"，而是被一条动机链串起来的。

| 幕 | 区域 | 守的东西 | 首领 | 在故事里干什么 |
|---|---|---|---|---|
| 序章 | 青云集（东南） | — | — | 醒来、认人、认路 |
| 第一幕 | 北坡乱葬岗（东北） | **阴土** | 千年树妖 | 山贼在挖坟，挖的就是这个 |
| 第二幕 | 南岭竹海（西南） | **竹心** | 青鳞蟒 → 机关傀儡 | 买家要的第二样 |
| 第三幕 | 西荒石窟（西北） | **石髓** | 石母 → 火鸦王 | 第三样，也是古洞侧壁 |
| 终章 | 青云古洞（最北） | — | 无面剑客 | 开碑、见自己 |

**序章 · 青云集**
主角在土地庙醒来，只记得一场火。柳三娘收留了他，说"你这身伤，不像山贼打的"。
- 教学：打第一只山贼、第一次进村、第一次打坐
- 悬念：庙里的碑文被人凿掉了名字，凿痕是新的
- 钩子：夜里有人在村口墙上画了个记号，第二天就没了

**第一幕 · 北坡乱葬岗（阴土）**
山贼不抢粮了，全往东北的坟地里挖。跟过去才发现，他们挖的不是陪葬，是**坟底三尺的阴土**。
- 节点：坟外围 → 山贼哨营 → 守墓人小屋 → 挖开的合葬墓 → 千年树妖
- 生态：白天坟地只有零星阴魂，夜里阴气翻倍、鬼火成片；守墓人白天是 NPC，夜里是精英怪
- 转折：树妖死时吐出一枚无字木牌，牌背刻着三道纹 —— 三道，不是一道
- 收束：寨主（原黑风寨主，就地并入本幕）临死说"我只是替人挖土。三样东西，他们只要三样。"

**第二幕 · 南岭竹海（竹心）**
木牌第一道纹指向西南竹海。竹海深处有座砍不倒的老竹，竹心里裹着东西。
- 节点：竹海入口 → 猎户棚（营地一） → 竹桥与溪涧 → 砍竹人的坟 → 青鳞蟒 → 机关傀儡
- 生态：竹海里有自己的活法 —— 猎户、采药人、逃兵三拨人互相提防；竹林可以被砍倒挡路，也会被怪撞断
- 机制：雾天视野压缩到平时的六成，靠听声辨位；青鳞蟒缠树，机关傀儡守着一座不该存在的工坊
- 转折：工坊里有图纸，画的是**青云古洞的封碑结构**。落款处的名字被磨掉了
- 收束：竹心取出时，工坊墙上有新鲜剑痕 —— 有人比你先到，又走了

**第三幕 · 西荒石窟（石髓）**
第二道纹指向西北。矿道往下走，越走越黑，只能靠火把。
- 节点：矿口 → 塌方区 → 矿工营地（营地二，半塌，还有活人） → 火鸦巢 → 石母 → 火鸦王
- 生态：矿工被困在下面出不来，靠火鸦王的蛋过活；他们知道路，但要你先替他们清一段
- 机制：洞内全黑，火把会灭，灭了要重新点；石母会拉塌顶，火鸦王会撞灭火把
- 转折：矿道最深处打通了 —— 通的就是古洞侧壁。他们挖了三年，只差最后三尺
- 收束：石髓到手，三道纹齐了。回村时柳三娘第一次没笑

**终章 · 青云古洞与无面**
三物开碑，下洞。遇到"无面剑客" —— 他不说话，招式却和主角一模一样。
- 节点：洞内三层 → 无面剑客（三阶段，每阶段换一种兵器） → 记忆碎片 → 选择
- 揭示：主角曾是这一脉的守碑人，那场火是自己放的
- 选择（不设对错，只影响后续 NPC 态度与结局旁白）：
  - 「记起来」→ 继承守碑人身份，侠名大涨，但村里人开始怕他
  - 「放下」→ 烧掉木牌，侠名不变，柳三娘会多留他一晚

> 关键设计一：**不写"你是天选之子"**。主角的身份是自己挣的，不是血统给的 —— 这是"代入感"的来源。
>
> 关键设计二：**三区各有各的人**。竹海有猎户与逃兵，石窟有被困的矿工，坟地有守墓人 ——
> 玩家记住的往往不是首领，是那个在雾里喊他别往前走的猎户。这是"两营地要具备生态"落到剧情上的样子。
>
> 关键设计三：**无面剑客一路留痕**。三区结尾都有新鲜剑痕，玩家会先恨他、再怕他、最后发现那是自己。
> 三次剑痕的形态递进：一道劈开坟土 → 一道削断竹桥 → 一道钉在矿道木梁上。

### 4.4 代入感的四个抓手

| 手法 | 做法 |
|---|---|
| **称呼变化** | NPC 从"这位少侠"→"你"→直呼其名，靠侠名等级推进 |
| **记忆** | NPC 记得你上次买过什么、杀过几只怪、有没有在他店里打过架 |
| **选择有回响** | 帮猎户找尸体会让他后来在洞里救你一命 |
| **沉默的重量** | 不是每句话都有用。有些 NPC 只说"……"，玩家反而会记住 |

**六种触发器**

| 类型 | 什么时候播 | 用在 |
|---|---|---|
| `boot` | 开局第一次 | 序章：睁眼 |
| `enter` | 走进某个地标半径 | 进村认人 / 坟地 / 竹海 / 矿口 / 塌方 |
| `item` | 持有某件信物 | 阴土 / 竹心 / 石髓 → 三道纹 |
| `time` | 到某个时辰（可叠前置 flag） | 子时墙上的记号 |
| `triple` | 三物齐 | 封碑 |
| `kill` | 杀某类怪 / 某首领 | 框架已支持，留给 P8/P9 用 |

**为什么不写 `talk` 触发器**：对话面板那一个点击位已经给了「接任务 / 复命 / 打听 / 作别」，
再塞剧情进去，玩家点一下永远猜不到会发生什么。**一个点击位只做一件事** ——
剧情统一走"条件满足自动播"，玩家不点也不会错过。

**三物线索系统**

三件东西不是"顺路打怪掉的"。每拿一件，无字木牌上就多亮一道纹，
多出来的那道纹指出下一件在哪 —— 玩家不看任务列表也知道该往哪走。

```
坟地（阴土）→ 第一道纹 → 西南：竹海
竹海（竹心）→ 第二道纹 → 西北：石窟
石窟（石髓）→ 第三道纹 → 正北：古洞
```

线索与任务刻意分开：任务有「完成 / 未完成」，线索只有「知道 / 不知道」。
**漏掉一条线索不该卡住玩家** —— 线索只影响木牌上有没有那道纹，
不影响能不能打、能不能开门（开门看三物本身）。

**三层对话**

不是三段不同的台词，是**同一个人对同一个人**的态度变化。门槛用侠名（5 / 30），
因为侠名是这个世界里唯一"别人怎么看你"的度量。
称呼是最便宜的信号：从「这位少侠」到「你」，一句话就能让人感觉被记住了。
**深交层不再称呼** —— 熟人之间不称呼。

| 层 | 侠名 | 口气 |
|---|---|---|
| 初见 | 0~4 | 客气、有距离、说事不说人 |
| 熟识 | 5~29 | 用「你」，会主动多说一句自己的事 |
| 深交 | 30+ | 不称呼，直接说事；有些人开始说不敢说的 |

| 计划 | 实际 | 为什么 |

| `talk` 也是触发器之一 | 去掉，只剩五种 + `triple` | 一个点击位只做一件事 |
| 剧情日志放行囊「旧事」页 | 同 | 与计划一致 |

**第 7 种触发器 `floor`**

终章发生在古洞里，而古洞不是一个"地标"—— 它是三块每次进去都重排的房间，
玩家在里面的坐标没有叙事意义，有意义的是"第几层"。硬拿 `enter` 去凑，
只能把地标钉在洞口，"下到第三层"这件事就写不出来了。

语义是 **`≥ N`** 而不是 `= N`（从三层回一层，二层那段不该重播），
而且"不在洞里时算 0"（`dgFloor` 是全局变量，离开古洞不会归零）。

**`onEnd.choice`：P7 以来第一次真的动运行时**

```js
onEnd: {
  choice: {
    prompt: '这件事没有对错。',
    options: [
      { id: 'remember', label: '记起来', hint: '把名字刻回碑上',
        flag: 'chose_remember', fame: 12, msg: '…', lines: [/* 结局旁白 */] },
      { id: 'letgo', label: '放下', hint: '把木牌烧了',
        flag: 'chose_letgo', msg: '…', lines: [/* 结局旁白 */] },
    ],
  },
}
```

`storyAskChoice()` 摆两个按钮 → `storyChoose(id)` 结算并压印 220ms →
`storyPickGo()` 放行，接着播结局旁白（选择是"你做了什么"，旁白是"后来怎样了"，
两段必须分开播，挤在一屏里会被当成选择的说明文字）。
